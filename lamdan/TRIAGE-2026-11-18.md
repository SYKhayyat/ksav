# lamdan, triaged — 2026-11-18

`PLAN.md` carried one line for two months: *"Run `lamdan` across the whole repo
once and triage its findings into this plan."* Three reports sit in this
directory, dated 2026-08-09 and 2026-08-18, and none of their findings had ever
been routed anywhere. This is that routing.

It is not a re-run of the audit. It is a **verdict per finding**, taken by
opening the file each one names and reading it, and nothing else. Two outcomes
are recorded, and a third is recorded as what it is:

- **closed since** — the code says the finding was fixed, and usually the
  comment says why, which is how this repository keeps its own history;
- **live** — the finding is still true today, and it has an issue number;
- **unverified** — I did not open it in this pass. Recorded as unverified rather
  than assumed fixed, because the reports are three months old and *most* of what
  they found has since been swept, which makes "probably fine by now" the most
  dangerous sentence available here.

The report's own thesis is about this repository, and the triage is the test of
it: *"arrives at the correct diagnosis, writes it down better than almost any
repository I have read, fixes the instance in front of it, and then does not
sweep for the siblings."* What the sweep found is that the siblings were swept —
by later sessions, one class at a time — but nobody had ever gone back to the
reports to say so. That is the gap this file closes.

## The second pass — every row verified (#210)

The first pass left seventeen rows marked *unverified*. The second pass opened
every one of them, and the answer was uniform enough to be worth stating once:
**the whole external report had been swept** between August and November, one
class at a time, and nobody had gone back to the report to say so.

Of the forty, **thirty-seven are closed since** and three are out of scope
(`girsa-personal`'s log, and two `sefer-crates` claims). Of the twelve
duplication findings, nine are closed, one is live-now-fixed, one is now a
documented refusal, and one is a cross-repo change this repository does not own.

Verifying them produced three things the reading alone would not have:

1. **`convertNote` had no caller.** The function `§6.2` complained about was
   still shipped, language-blind and command-based, and its only consumer was a
   test — a fence around dead code that read like a fence around the feature.
   Deleted; the test's substantive claims moved onto `retargetNote`, which is what
   the note menu calls.
2. **The CLI printed `✓ compiled` before it counted the page images it could not
   write** (`§5.2`). The count and the exit code were right; the order was not, so
   a run whose page images all failed said `✓ compiled … (43 page(s))` and then
   `✗ 43 of 43 …` and exited 1. `engine/tests/cli.rs` now runs the built binary as
   a process against a page-image path that is a directory, which is the failure
   the report describes and the one a permissions test would miss on Windows.
3. **A settings write that fails had no test at all** (`§4.4`), only the code and
   the comment. `settings.test.mjs` now breaks `localStorage.setItem` on purpose
   and asserts that the failure is observable, that the shell is told *once* for a
   run of failures, and that a success clears it.

Each of those three is mutation-tested in the way this repository means it: break
the code, watch the named assertion go red, restore.

One row could not be given a behavioural fence and says so rather than
pretending: `store.forEach`'s throwing visitor (`§5.6`). `fake-indexeddb` re-raises
a throw from an event handler into the abort path, so deleting the guard leaves
the behavioural assertion green — the browser hangs and the test runtime does not.
That row therefore has *both*: the contract asserted (the walk settles with the
visitor's error and the connection still works), and a source rule that the guard
is there, which does go red when it is removed.
